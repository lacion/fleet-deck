## Sole bootstrap runtime and P4 deletion

[`createBootstrapProcessRuntimeBridge`](../../../../src/daemon/app/bootstrap-process-runtime.ts) is
the only pre-root runtime crossing. It constructs at most one
`ManagedRuntime.make(ProcessRunnerLive)`, lazily on the first admitted request. It tracks each
Effect `Exit`; `quiesce()` synchronously closes admission and interrupts active work, while one
published `close()` Promise joins those Exits before `runtime.dispose()` releases the Layer and
joins any remaining driver cleanup.

[`fleetd.ts`](../../../../src/daemon/fleetd.ts) creates and registers that owner before SQLite or
core acquisition. [`DaemonResources`](../../../../src/daemon/daemon-resources.ts) quiesces it before
HTTP/core/producers, closes admitted callers and core, then disposes the runtime before SQLite and
the owned pidfile. A failed process-runtime close makes SQLite intentionally remain open until
process exit rather than permit a late callback against a retired handle.

P4 has an atomic deletion condition:

1. remove the bootstrap bridge creation/registration and
   [`bootstrap-process-runtime.ts`](../../../../src/daemon/app/bootstrap-process-runtime.ts);
2. prove no bootstrap `ManagedRuntime` can be constructed;
3. bind the still-temporary `execFileP` delegate exactly once to the root `IngressSupervisor`;
4. retain `ProcessRunnerLive` inside the one root Layer and its ordered lifecycle coordinator.

The P3 bridge and P4 root interpreter must never be live together. The Promise facade may remain
for legacy callers until its scheduled cleanup, but after P4 it must be backed only by the root
supervisor.
