## Sole bootstrap runtime and P4 deletion

[`createBootstrapProcessRuntimeBridge`](../../../../src/daemon/app/bootstrap-process-runtime.ts) is
the only pre-root runtime crossing. It constructs at most one
`ManagedRuntime.make(ProcessRunnerLive)`, lazily on the first admitted request. It tracks each
Effect `Exit`; `quiesce()` synchronously closes admission and interrupts active work, while one
published `close()` Promise joins those Exits before `runtime.dispose()` releases the Layer and
joins any remaining driver cleanup.

[`fleetd.ts`](../../../../src/daemon/fleetd.ts) creates and registers that owner before SQLite or
core acquisition. [`DaemonResources`](../../../../src/daemon/daemon-resources.ts) quiesces it before
HTTP/core/producers, closes admitted callers and core, then disposes the runtime before SQLite and
the owned pidfile. A failed process-runtime close makes SQLite intentionally remain open until
process exit rather than permit a late callback against a retired handle.

P4 has an atomic deletion condition:

1. remove the bootstrap bridge creation/registration and
   [`bootstrap-process-runtime.ts`](../../../../src/daemon/app/bootstrap-process-runtime.ts);
2. prove no bootstrap `ManagedRuntime` can be constructed;
3. bind the still-temporary `execFileP` delegate exactly once to the root `IngressSupervisor`;
4. retain `ProcessRunnerLive` inside the one root Layer and its ordered lifecycle coordinator.

The P3 bridge and P4 root interpreter must never be live together. The Promise facade may remain
for legacy callers until its scheduled cleanup, but after P4 it must be backed only by the root
supervisor.

**Closure note.** The original P3 acceptance required a paired, same-machine P0→P3 comparison: two
quiet P3 runs passing the strict within-phase comparator, then a P0→P3 delta extracted from the
immutable P0 and P3 JSON. **That comparison is not measurable at the current branch HEAD
(`9bbe391c`)**, for two independent structural reasons (detailed in the **Final closure** section):

1. **The measured subject no longer exists at HEAD.** P4 atomically deleted the P3
   `BootstrapRuntimeBridge`; the exec harness at HEAD binds the root `IngressSupervisor` through
   `makeIngressExecFileDelegate`, so a run here exercises the P4+ root path, not the P3 bootstrap

## Final closure: adaptation and supersession

The P3 ledger item — "paired quiet-host performance evidence" — is closed here by honest adaptation.
The two structural reasons it is not measurable as originally specified are stated in the
benchmark-tables **Closure note** above (P4 deleted the measured P3 subject; the macOS checkpoint
host is unavailable and the machine-aware comparator rejects cross-host compares). The item is
discharged in two halves.

**Daemon / HTTP half — superseded.** No post-P3 package re-ran the P3 daemon baseline as its own
artifact; the daemon path was instead converted and re-measured downstream. P4 recorded root-runtime
idle/forced-shutdown and residue evidence, and P6.8 recorded a legitimate *within-host* legacy-vs-
Effect HTTP/WS comparison on this same quiet WSL2 host (12/12 `/health`+`/state` p95 cells within the
+10% line). Those are the same-host comparisons the P3 daemon budget wanted; the macOS P3 daemon
numbers are a stale, unreachable baseline and are not resurrected.

left "the process-p95 half" to the P0 exec bench, so the exec surface was the one half with no

the exact P0 harness configuration (100 warmups, 1,000 short commands, 5 scenario iterations, 250 ms
timeout, 1 MiB combined cap) on the pinned Bun floor `1.3.14` rev
`0d9b296af33f2b851fcbf4df3e9ec89751734ba4`. These numbers exercise the **P4+ root `IngressSupervisor`
