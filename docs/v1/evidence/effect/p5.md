## Production wiring

P5 background work is integrated into the production daemon root:

- [`prepareBackgroundOwner`](../../../../src/daemon/app/background-owner.ts)
  separates cold preparation from one idempotent fiber start. Readiness is
  available to native acquisition before the daemon-long fiber is admitted.
- [`makeDaemonBackgroundProgram`](../../../../src/daemon/app/background-program.ts)
  owns boot reconciliation, retention, agents polling, and LAN refresh as one
  aggregate program.
- `AppConfigLive` replaced the transitional root configuration service.
- `acquireDaemonResources` receives the prepared Background service/controller
  and returns a cold background program.
- The live Layer starts and registers the single Background owner before
  lifecycle ownership is sealed, then publishes both `Background` and
  `DaemonLifecycle`.
- The root waits on `Background.awaitFailure` instead of an unconditional
  `Effect.never`.
- The legacy boot Promise chain, legacy agents-poll start, and legacy
  network-watch start are no longer production entrypoints. The in-tree legacy
  agents and network implementations remain as compatibility surface, not as
  the live cadence owners.
- `createCore` no longer owns the boot retention sweep or ten-minute retention
  interval. It exposes narrow `retentionSweep` and `pruneEvents` capabilities
  for the Effect schedule.
- Legacy agents and network cadence timers are no longer unref'ed; explicit
  owner shutdown governs natural exit. The join-timeout timer inside the
  Background owner and the existing one-second mDNS-stop watchdog remain
  unref'ed; those are not the converted scheduler cadence timers.
- A real BunRuntime fixture proves the three async scheduler finalizers finish
  before store close, callbacks remain stable afterward, and the process exits
  naturally without `process.exit`.
- The sole `Effect.cached` startup wrapper was replaced with a cold,
  single-assignment `Deferred` gate (`a1a5a639`).

Schedule policy uses `Schedule` (agents poll is `Effect.repeat` +
`Schedule.spaced`; LAN uses the fixed-grid helper) with `TestClock` in the
focused units and a real Bun-clock natural-exit fixture. The question orphan
sweep was **not** moved; it remains the explicit P1 handle in
[`questions.ts`](../../../../src/daemon/questions.ts) until P10, which is the
allowed P5.5 choice.

## Gate 1 — prompt top-level background failure

Closed by `02d25b62`.

Each of the four top-level background children is wrapped in `Effect.onExit`
(`observe` in `background-program.ts`) so every unexpected non-success exit is
published to the ready/failure latches via `controller.observeChildExit`
(first-wins `Deferred.doneUnsafe`) **before** the aggregate sibling join.
Requested-shutdown interrupts are suppressed through a shared
`shutdownRequested` box that `interrupt()` flips synchronously before
`fiber.interruptUnsafe()`.

Regression:
[`tests/effect/background-prompt-failure.test.ts`](../../../../tests/effect/background-prompt-failure.test.ts)

- (a) a defecting child fails the root promptly while a sibling is stuck in a
  never-settling `ownedLegacyPromise`, within a bounded close;
- (b) requested shutdown does not trip the failure latch.

Mutation check: neutralizing the observe wrapper makes test (a) fail.

Adversarial review (independent model, grok-4.6): verdict **SHIP**, zero
findings across eight attack angles, verified against `effect@4.0.0-rc.110`
internals (`OnExit` is an uninterruptible stack continuation completing before
`FiberImpl` publishes the exit to observers; `forEachConcurrent` reacts only
via `addObserver`; `Cause.hasInterruptsOnly` cannot suppress mixed
defect+interrupt causes).

One noted benign delta: `owner.close()` after a prompt defect can resolve as
requested-interrupt instead of rejecting `BackgroundDefectExitError`.
Production shutdown keys off `Background.awaitFailure`
(`shutdownTriggerFromExit`), not `close()`'s Promise.

## Gate 2 — detached-owner exception

Accepted and recorded. The single `Effect.forkDetach` in
[`background-owner.ts`](../../../../src/daemon/app/background-owner.ts) is the
one reviewed deadline-bounded detached owner. It exists so a stuck legacy
Promise cannot make root Scope closure exceed the P4 hard deadline. The owner
is manually registered, interrupted, and bounded-joined. Making every legacy
bridge cancellation-bounded now was rejected; those bridges are slated for
replacement in later packages.

This is the P5 exception to the ledger's former “detached work: None
permitted” statement. It is not a new process-independent child, and it is not
an untracked `forkDaemon`.

## Fixture closures on the same slice

`d53e57a3` and `ca62b94f` did not weaken assertions or raise budgets:

1. Packed-install smoke reconstructed the bundle recipe while redirecting only
   `--outfile`, so the new PURE-strip post-step mutated the committed bundle
   and compared an unstripped scratch build. The verifier now substitutes the
   tracked path across the recipe tail.
2. The P1 clone shim armed its TERM/INT trap after writing its readiness file
   (trap-window race, measured 6/300 failures at 44-way CPU oversubscription,
   0/300 trap-first). The trap is now armed first.
3. The acquisition fixture leaked `FLEETDECK_TEST_DAEMON_SCRIPT` into its
   child, so bundle-mode runs emitted the boot seam banner and broke the
   empty-stderr assertion. The seam var is scrubbed from the child env.
4. The shim's foreground sleep loop left dash a window where a pending
   group-SIGTERM was unserviced until the sleep child exited. POSIX: the
   `wait` builtin, unlike foreground `waitpid` on a command, is interrupted by
   a trapped signal immediately. Replaced with `sleep 1 & wait`. Differential
   bisection: `tests/process-driver-reference.test.ts` immediately before
   `p1-spawns-lifecycle` reproduced 3/3 pre-fix, 5/5 green post-fix; four
   other driver-heavy prefixes never failed, so it was that pair, not generic
   warmup. The 2000 ms budget was not raised.
