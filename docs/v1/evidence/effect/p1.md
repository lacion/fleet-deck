# P1 explicit resource-handle checkpoint

P1 completed on Bun `1.3.14` (`0d9b296a`) at implementation commit `a8e4c9b`.
The daemon remains imperative at this checkpoint, but every resource that can
currently be stopped is reachable through one plain `DaemonResources.close()`
path before the Effect runtime is introduced.

## Ownership established

- HTTP quiesce, held-hook fail-open, Bun listener shutdown, request draining,
  snapshot and terminal WebSockets, keepalive/broadcast timers, watch waiters,
  and the terminal bridge.
- Terminal viewers, input/capture waiters, timers, control-process TERM/KILL,
  direct-child reaping, inherited pipe teardown, and re-entrant double close.
- Questions, hold/rearm/orphan/completed-key timers, retention cadence and
  in-flight sweeps, mail timers/delivery, repository-origin backfill, clone
  provisioning, liveness/reconciliation, deferred adoption, remote harvest,
  nudge and succession timers.
- LAN refresh and agents polling, including joining an already accepted poll
  and suppressing its late result during shutdown.
- Ordered aggregate closure: refuse ingress and producers, release holds while
  HTTP can still answer, close transports and core maintenance, close SQLite
  only after every potential user reports successful closure, and remove the
  owned pidfile last.

Legacy subprocess interruption remains the named P3/P5 boundary. P1 joins the
cleanup available from existing subprocess owners; it does not add a blind
deadline that could retire SQLite underneath accepted work.

## Verification

Commands were run from the repository root on the implementation tree:

```text
bun run bundle
bun run typecheck
bun run typecheck:board-tests
bun run ci
bun test --timeout 300000 <P1 focused matrix>  # 123 pass, 0 fail
bun test --timeout 300000                      # 1,260 pass, 1 skip, 0 fail
bun run test:bundle                            # 1,251 pass, 10 skip, 0 fail
npm pack --dry-run --json --ignore-scripts
bun scripts/effect-migration/p0-exec-bench.ts --out <p1-exec.json>
bun scripts/effect-migration/p0-compare.ts --left docs/v1/evidence/effect/exec-run-1.json --right <p1-exec.json> --out <comparison.json>
```

The exec comparator passed all eight health/equality checks and reported the
same stable-evidence hash. The unchanged legacy exec workload measured p50
`8.525 ms` versus `10.254 ms` at P0 (`-16.862%`), p95 `-0.786%`, and p99
`+0.140%`; this is normal run variance, not a production exec change.

the plain aggregate with the root coordinator, and later packages remove the
legacy resource machinery after service migration.
