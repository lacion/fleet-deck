## 3. Adversary DESIGN REVIEW of ADR-004, PLAN §8 and §9 — verdict FAIL

The adversary confirmed several parts as correct:

- The transcript signatures bind the TLS exporter, both raw Hellos, both keys, and the sender side.
- Invitations are consumed under one lock.
- The D13 address rules cover IPv4-mapped IPv6 and wildcard addresses.
- 94 `s4-link` tests passed.

The adversary also found 12 defects. The architect decided each fix below. All items are marked **M2**. Items G1–G7 change the protocol contract. Do them first in Phase 3: update ADR-004 and PLAN §8/§9 (add a "Revision 2 (M1 gate)" section to ADR-004), then implement them in `fleetdeck-link`. Do not fix them in the spike. Items G8–G12 are implementation defects: fix them in `fleetdeck-link` and give each one a test.

| Id | Finding | Decision (binding for M2) | Test that proves it |
| --- | --- | --- | --- |
| G1 | Reciprocal or parallel links escape the duplicate-link rule (the dialer has no link table, each listener has its own table, and epochs come from the wall clock). | One node-wide link table keyed by the peer key fingerprint. It covers inbound and outbound links and all listeners. The `link_epoch` is a persistent per-peer counter of the dialer, stored in SQLite and incremented (and committed) before each dial. It does not come from the wall clock. Each attempt also has a random 128-bit `attempt_id`. The data channel binds to the `attempt_id`. When a second link to the same peer reaches Ready: (a) same dialer: the higher epoch wins; (b) opposite dialers: the link dialed by the node with the lower key fingerprint (bytewise) wins. Both sides compute the same result. The losing link closes with `superseded`. Frames of a superseded attempt are dropped before they reach the application. | Simultaneous reciprocal dials; two listeners on one node; a stale epoch after a restart is refused. |
| G2 | Data credit does not bound memory. | Per-link budgets: at most 64 open streams; a per-stream window of 256 KiB; at most 4 MiB of buffered inbound bytes for the whole connection. Bytes count until the application consumes them, also after a stream reset. All queues are bounded: control inbound and outbound hold 256 messages each, and pending writes count against the budget. An empty data frame is a protocol error. A reset for an unknown stream is ignored and makes no event. A budget violation closes the link with `flow_control_violation`. The reader and the writer stay independent tasks. | An open/send/reset flood stays under the budget and ends with `flow_control_violation`; an empty data frame closes the link. |
| G3 | A reconnect can repeat a command after the station lost its receipts (database reset or receipt expiry). | Each mutating command carries `target_incarnation` and `retry_until` (deck UTC time; the default is accepted-at + 15 min). The deck stores the envelope, which does not change after it is stored. The station rejects a command whose `target_incarnation` is not its current incarnation (`incarnation_mismatch`), or whose `retry_until` is in the past by more than 2 min of skew allowance (`expired`). It writes no receipt in both cases. The deck never resends after `retry_until`. A command that was sent and is not acknowledged before then becomes `ambiguous`. A rejected command that was sent before becomes `ambiguous`. A rejected command that was never sent becomes `failed: station_reset`. Nothing is redispatched automatically. Stations keep receipts for at least 24 h, which is more than the retry horizon. | Commit, lose the response, reset the station database, reconnect: the command is `ambiguous` and not executed twice. A receipt-expiry variant gives the same result. |
| G4 | The snapshot fallback cannot set a complete cursor. | Every `Event`, `Ack`, and snapshot frame carries `incarnation`. A snapshot is a batch: `SnapshotBegin { incarnation, watermark, session_count }`, then `SnapshotSession` × N, then `SnapshotEnd { watermark }`. The deck applies the whole batch and sets the cursor to `watermark` in one transaction at `SnapshotEnd`. Sessions that are not in the batch are marked `removed`. A batch without its end has no effect. An `Ack` with a different incarnation, or with a sequence higher than the delivered watermark, is a protocol error. | History truncation with 3 sessions, one deleted: after the snapshot the deck has exactly the 2 live sessions. An interrupted batch changes nothing. |
| G5 | A revocation leaves the open link working. | A revocation removes the pin and all grants of that key in one transaction and increments a revocation generation. It closes every active link of that key within 1 s. The decision transaction of each command checks, in the same transaction, that the pin and grant still exist. So a queued command from a revoked link is rejected. A key rotation replaces the key in one transaction. The new key gets only the role and grants of the old key. The old key is revoked as above. | `forget-deck` during an open link: the link closes and a command that was already queued is rejected. |
| G6 | Frame authorization does not check roles or features. | The method table gets `caller_role` and `receiver_role` for each method. Event, Ack, and snapshot frames get a fixed direction: events and snapshots go station → deck, and acks go deck → station. Every frame is checked against the roles that were bound at pairing, never against the dial direction. Snapshot frames need the negotiated `snapshots.v1` feature. A data stream can open only with a single-use stream token. A control response that authorized the operation issues the token. A free `purpose` string is not enough. | A wrong-direction Ack, a Snapshot without the feature, and a data stream without a token are all refused. |
| G7 | `coordinator.call` is marked non-mutating in ADR-004 but mutating in the code. | Coordinator operations that change fleet intent are mutating. They need a `command_id`, and the deck keeps receipts and deduplicates them, with the same rules as station receipts. Read operations stay non-mutating. ADR-004, the generated method table, and the tests must agree. A test compares the ADR table with the code table. | A table-agreement test; a duplicate coordinator call is deduplicated. |
| G8 | Control backpressure can block shutdown and reconnect, and there is no heartbeat. | Socket writes and application delivery run outside the cancellation `select`. Every write and cleanup step has a time limit (close: 1 s). A heartbeat ping runs every 15 s, and the link closes if no frame arrives for 45 s. At most 128 requests can be outstanding on one link. Shutdown never waits for queue capacity. | A full application queue does not block supersession or shutdown; a blackholed peer is detected in less than 50 s (with an injected clock). |
| G9 | A stream reset strands pending writes. | A reset removes the pending queue of the stream and fails each waiting write at once. Stream ids are never reused within one attempt. | A large write that waits for credit fails right after a peer reset. |
| G10 | A failed setup leaves a stale link-table entry. | Generation-aware cleanup is installed right after the table insert and runs on every failure path. Superseded setup waits are cancelled. | Failure injection at Ready and at data-channel setup: the table is empty after each failure. |
| G11 | Wrong proofs from anyone can cancel all invitations. | No global cancellation. The invitation id is the non-secret part of the invitation. Failures are counted for each invitation id: 5 failures cancel only that invitation. Each source IP can make at most 10 pairing attempts per minute, and at most 4 pairing handshakes can run at the same time. | After 5 wrong proofs for invitation A, invitation B still works; a new invitation works after a rate-limit lockout ends. |
| G12 | Invitation secrets appear in argv and in event output. | `fleetdeck station join` and `fleetdeck deck add-station` read the invitation from a non-echoing prompt, from stdin, or from `--invite-file` (mode 0600 required). They never take it as an argument. The invitation shows only once, on the owner's terminal or in the board's pairing dialog. It is `Secret<T>` everywhere else and is redacted in logs, traces, and events. | A log-capture test finds no invitation secret; the CLI refuses an invitation given as an argument. |
