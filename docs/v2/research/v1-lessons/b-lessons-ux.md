## docs/orca-lessons.md
- Summary: A v0 (v0.22.3, 2026-08-07) analysis of Orca, an Electron "Agent Development Environment". It lists what Fleet Deck matched, where Orca led, and what to reject. It is an analysis, not a plan.
- It was written for a v0 membrane product (plain `claude` plus hooks). v2 now drives agents through their protocols, so the "reject" table is partly obsolete.
- Paths below are in the v2 worktree.

Ideas and lessons:
1. Agent-drivable control surface with a waitable orchestration lifecycle (Run, Task, Dispatch, Message, Decision gate). The coordinator blocks on a FIFO inbox for `worker_done` / `escalation` / `question`, and workers escalate questions upward. v2 status: partial. The coordinator MCP exists with tools `fleet_status`, `list_tasks`, `wait_task` (60 s deadline). I found no worker-to-coordinator escalation tool and no decision gates. Evidence: docs/v2/adr/ADR-006-coordinator-mcp.md §6.3 (lines 159-177: "Coordinators never answer approval or question requests in M3"). Value: high. This is the main way to run a fleet without a human at the keyboard.
2. Typed, waitable completion events (a coordinator blocks until worker N is done or asks). v2 status: partial. `wait_task` waits on a task. No "wait for any worker event" (done / question / error) was found. Evidence: ADR-006 §6.3 (`wait_task { task_id }` only). Value: medium. One long-poll over many sessions would simplify coordinator prompts.
3. Group addresses (`@all`, `@idle`, `@claude`, `@codex`, `@worktree:<id>`) for mail. v2 status: partial. Mail goes to a chosen session, a station, a repo, or everyone. No provider or idle selector found. Evidence: docs/v2/PARITY.md line 64 ("mail to a station, a repo or everyone"). Value: low. Add `@idle` and `@provider` only if coordinators ask for it.
4. Scheduled automations (cron or preset, a prompt run in a worktree, a shell precheck that records a "skipped" run, missed-run grace, `--reuse-session`). v2 status: missing. Evidence: no match for schedule/cron/automation in docs/v2 or crates/. Value: medium-high. "Every weekday, spawn a triage worker" fits the deck, because the deck is always on. It must stay deterministic (no model call to decide).
5. Diff viewer against the worktree start ref, per file, with stage-hunk and keyboard hunk navigation. v2 status: partial. A per-turn diff and a revert exist. A whole-worktree diff against the start ref was not found. Evidence: web/src/session/TurnsPanel.tsx (per-turn `TurnDiff`, `Diff` component), web/src/chat/Diff.tsx, crates/fleetdeck-station/src/store/turn_checkpoints.rs. Value: high. The harvest step ("what did this agent change in total?") is the most common review action.
6. Annotate the AI diff: line-anchored comments, batched into one prompt ("send notes to" an agent). Rationale: one batch gives one revision pass and a higher hit rate. v2 status: missing. Evidence: no "annotat" or line-comment code in web/src. Value: high. It reuses the composer and follow-up mail, and needs no model.
7. Usage and rate-limit awareness: reset windows, a warning chip at 80 %, bars sorted tightest-first, cost from a local price table. v2 status: partial. Meters per provider scope exist, with a `high={80}` threshold. The sort is alphabetical by key, not tightest-first. No reset-time countdown was seen in the meter text, though `resetsAt` is in the data. Evidence: web/src/board/UsageMeters.tsx:45, web/src/board/usage.ts:51-88, crates/fleetdeck-providers/src/codex/limits.rs. Value: medium. A tightest-first sort and a "resets in 2h" label are small changes.
8. Account hot-swap (rewrite the credential pointer; affects new sessions only). v2 status: missing. v2 keeps credentials on the station and never reads them. Evidence: docs/v2/PLAN.md line 93 (rule 6). Value: low. It conflicts with rule 6 unless the station does it locally.
9. Cmd-J "worktree jump" palette: jump across worktrees and tabs, match PR numbers, show a "create worktree" row when nothing matches. v2 status: partial. A "Go to session" palette exists on Mod+K. It has no create row and no PR match. Evidence: web/src/app/Palette.tsx, web/src/app/keys.ts. Value: medium. The "no match, so offer to spawn" row is cheap and helps at 15+ sessions.
10. Cmd-P file search in the current worktree. v2 status: partial. The Files panel and a global Files page browse and search files. Evidence: web/src/session/FilesPanel.tsx, web/src/app/FilesPage.tsx. Value: low.
11. Task-to-worktree: spawn from a GitHub / Linear / Jira issue; prefill the name; "fix broken checks" hands the failing checks to an agent. v2 status: partial. PLAN says "issue-driven spawns default to supervised" (a design rule). I found no issue browser or spawn-from-issue in the code. Evidence: docs/v2/PLAN.md line 536; "not found" in crates/ and web/src. Value: medium. Clone auth is already on the station (PLAN line 341), so this is a read-only slice.
12. Design Mode (capture element HTML, CSS, screenshot, source line and send it to the agent). v2 status: partial. Image paste exists. No embedded browser. Evidence: web/src/session/images.ts, web/src/terminal/paste.ts. Value: low. It needs a browser that v2 does not have.
13. SSH worktrees (agent and worktree on a remote host). v2 status: has, in another form. The station model puts the agent on the machine that owns the workspace. Evidence: docs/v2/PLAN.md (station owns execution, A1); docs/v2/t3code-lessons.md §3. Value: n/a, already the core design.
14. Hibernation (stop long-idle finished agents to free memory; resume on focus). v2 status: missing. Evidence: no match for hibern in docs/ or crates/. Value: low. Resume is native (`resume_tests.rs`), so a manual "park" would work. Memory pressure is untested in v2.
15. Fan one prompt across N agents is manual in Orca; v0 automated it with `3x`. v2 status: has. Evidence: docs/v2/PARITY.md line 18 (Spawn, batch, `Nx`; `web/e2e/spawn.spec.ts`). Value: n/a, an advantage to keep.
16. "Compare and merge the winner" after a race. v2 status: missing. Nothing compares the N sibling sessions of an `Nx` batch. Evidence: not found. Value: medium. It needs item 5 first (whole-worktree diff), then a side-by-side summary and a "keep this branch, archive the rest" action. Keep it deterministic.
17. Reject list: Electron app, agent-agnostic core, Computer Use, write-heavy GitHub ownership, hosted relay, an "AI picks the winner" step in the default path. v2 status: mostly still true. v2 is provider-aware (Claude and Codex adapters) but the core is provider-blind and makes no model calls. Evidence: docs/v2/PARITY.md lines 38 and 45; crates/fleetdeck-cli/tests/cutover.rs. Value: low. Keep "no model calls in the core" for any harvest or schedule feature.

## docs/t3code-lessons.md
- Summary: The v0 (2026-08-07) lessons from T3 Code. It frames the products as observe (v0) / host (Orca) / mediate (T3 Code). It ranks seven lessons and a "do not adopt" table.
- v2 chose the "mediate" side, so most of the reject table is now wrong for v2. v2 has its own newer file, docs/v2/t3code-lessons.md (2026-10-11), which supersedes this one. I note only what the older file adds.

Ideas and lessons:
1. Per-turn checkpoints with baseline, finalized diff, and revert (the strongest lesson). v2 status: has. Evidence: crates/fleetdeck-station/src/store/turn_checkpoints.rs, crates/fleetdeck-providers/src/claude/checkpoint.rs, link methods `session.revert` and `session.resolve_revert` (crates/fleetdeck-link/src/methods.rs:216-226), web/src/session/TurnsPanel.tsx. Value: n/a, done.
2. Per-card "what changed this turn" and "diff since spawn" on the board card. v2 status: partial. The session view has a turn diff, with "N files changed +a -b" (UI-DESIGN.md line 244). The fleet card has file chips (PARITY.md line 64). A "diff since spawn" total was not found. Evidence: docs/v2/UI-DESIGN.md:244, web/src/session/TurnsPanel.tsx. Value: medium.
3. ACP as the clean path to real status from non-Claude agents. v2 status: partial. v2 normalizes events from two native adapters. ACP is not implemented. Evidence: docs/v2/PLAN.md and docs/v2/t3code-lessons.md mention ACP; crates/ has no ACP adapter. Value: low-medium. Only needed for a third provider (Cursor, Gemini, Grok).
4. Corollary: hooks for membranes, SDK or protocol for clients that own the agent. v2 status: not applicable. v2 now owns the agent, so it uses stream-json and app-server. Evidence: docs/v2/adr/ADR-001-native-claude-adapter.md. Value: n/a.
5. A four-rung permission ladder (Supervised, Auto-accept edits, Auto, Full access) in place of one scary "unsupervised" checkbox. v2 status: has. A mode ladder lists modes from most restrictive, from provider capability. Evidence: web/src/session/SessionSettings.tsx:1-16 (DL-140), `modes` prop; web/e2e/session.spec.ts "the mode ladder". Value: n/a, done.
6. A per-card turn timeline as a projection over events. v2 status: has. Evidence: web/src/session/timeline.ts, web/src/session/TurnsPanel.tsx, crates/fleetdeck-deck/src/store/read_model.rs. Value: n/a, done. The remaining gap is a compact timeline on the fleet card (low).
7. Bring-your-own forge credentials, using the user's own `gh` / `glab` / `az` on the server, across four forges. v2 status: partial. The station clones with its own git credentials and the deck never holds forge tokens. No forge CLI integration (PR create, issue read) found. Evidence: docs/v2/PLAN.md:341; web/src/spawn/CloneAccess.tsx. Value: medium. It is the base for spawn-from-issue (Orca item 11). GitHub and GitLab both matter to this owner.
8. Server/client split, local-first, Tailscale route; decline a hosted relay. v2 status: has. The deck is a hub. The station dials the deck. Evidence: docs/v2/PLAN.md (topology), docs/v2/t3code-lessons.md §3. Value: n/a.
9. Contributor-facing `docs/internals` with a glossary. v2 status: has. Evidence: docs/v2/internals.md. Value: n/a, done. A glossary of terms inside the product is a separate item (see ux-feedback item 1).
10. Do-not-adopt table (SDK, event sourcing, replace the terminal, protocol-normalize, in-app PR workflow, hosted relay, LLM niceties). v2 status: reversed for the first four (v2 drives via protocols, event-sources, normalizes). Still true for hosted relay and for LLM calls. Evidence: docs/v2/t3code-lessons.md §1; docs/v2/PARITY.md:45 (no model calls in the core). Value: low. Do not use this table as v2 guidance.
11. In-app write-heavy PR workflow (commit, push, PR, suggested titles, stacked PRs). v2 status: missing, by design so far. Evidence: not found. Value: low-medium. A "push and open PR" action on a finished worktree is the natural end of the harvest arc, but it widens scope.

## Top 10 for v2
1. Whole-worktree diff against the start ref (Orca 5): a session has only per-turn diffs; reviewing a finished agent needs the total.
2. Line-anchored diff notes sent as one batched follow-up (Orca 6): the common review action has no board support, and it needs no model.
3. Show the real failure of an asynchronous spawn (ux 15, 16, 17): clone and setup errors must reach the user without opening a card.
4. Coordinator escalation and "wait for any worker event" (Orca 1, 2): a coordinator can wait on a task but workers cannot ask upward, so unattended runs stall.
5. Scheduled automations with a shell precheck (Orca 4): the deck is always on, so a deterministic cron spawn is a natural fit.
6. Compare and merge the winner of an `Nx` batch (Orca 16): v2 launches N siblings but has no way to pick one.
7. Terminal wall with view-only close per tile (ux 7, 8): deferred (DL-131); it is the live "watch the fleet" view.
8. Plan execute atomicity and "proposer still live" note (ux 9, 11): a failed start must not mark a plan executed; avoid a duplicate worker.
9. Spawn-from-issue using station-side forge CLIs (Orca 11, T3 7): the clone auth is ready; add a read-only issue list and a prefilled spawn.
10. Rate-limit meters sorted tightest-first with a reset countdown (Orca 7): the data (`resetsAt`) is there; the order and label are not.
