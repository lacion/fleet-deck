## docs/fleetdeck-v1.0.md
- Summary: The v1.0 product vision, dated 2026-08-07 (against v0.22.3). It synthesizes three competitive analyses. It widens the five doctrine rules to a multi-agent, multi-provider "command deck". Foundations: F1 TypeScript contracts-first, F2 Bun binary. Pillars: P1 Codex provider, P2 diff + notes + per-turn checkpoints, P3 issue/PR spawning, P4 usage + multi-account, P5 programmable fleet, P6 unified views + permission ladder.
- It is a vision and a sequence, not a spec. Its stack (Node, Bun, .mjs daemon, hooks) is replaced in v2 by Rust deck, stations and a React board. The product ideas still apply.
- Ideas and lessons:
1. Doctrine as a filter: no wrapper, fail-open, no model calls in the core, loopback by default, plugin not app. v2 status = partial. v2 keeps "no model calls" (test) and "never a hosted relay"; fail-open and "plugin not app" do not apply to a driven-session design. Evidence: `crates/fleetdeck-cli/tests/cutover.rs` `no_crate_calls_a_model_api_directly` (named in docs/v2/PARITY.md); PLAN A10 "A deck or network failure never stops a session" (docs/v2/PLAN.md:77). Value = medium: the written "doctrine test" list for new features is not in v2 docs; a short v2 version would help review.
2. F1 contracts-first typed boundary with `schema_version`. v2 status = has (stronger). Rust proto types generate the board's TypeScript; a drift test fails when output is stale. Evidence: `Makefile` target `ts-types`, `crates/fleetdeck-proto/src/ts.rs`, `web/src/gen`, PARITY row "Contracts first, `schema_version`, version negotiation" (`crates/fleetdeck-link/tests/version_skew.rs`). Value = low: done.
3. F2 single binary plus Homebrew as a distribution channel. v2 status = has. `cargo-dist` for Linux and macOS, installer, Homebrew tap, container image. The release itself is an owner step. Evidence: `crates/fleetdeck-cli/tests/packaging.rs`, docs/v2/PLAN.md:650, docs/v2/operations.md:190. Value = low: done; remaining work is the owner release step.
4. A DB adapter seam so the same code runs on two runtimes. v2 status = not applicable. v2 uses one Rust SQLite layer (`crates/fleetdeck-core/src/db.rs`). Value = low.
5. P1 second harness (Codex) as a first-class provider through one provider interface. v2 status = has, and driven, not only observed. ## docs/v1/ts-migration.md
- Summary: A playbook for moving 34 daemon modules from .mjs to .ts file by file. Marked partially superseded (Bun single runtime; Node floor deleted). It measures fan-in against size, then gives a six-step per-file recipe, an order of phases, a target folder layout and guardrails.
- Most of it does not apply to v2: v2 is Rust and has no file-by-file JS migration. Only the lessons below carry over.
- Ideas and lessons:
1. Order a migration by typing cost and boundary value, not by rename cost (fan-in vs size table). v2 status = not applicable (no migration pending). Evidence: v2 is a new Rust code base (`crates/`). Value = low. Use again only if the board `.tsx` gets a strict-mode tightening.
2. Put the contracts module first, with runtime validators on the hostile boundaries only (hook body, spawn body) and `schema_version` on each wire shape. v2 status = has. Evidence: `crates/fleetdeck-proto`, `crates/fleetdeck-link/tests/version_skew.rs` ("an event of a newer build is kept as unknown and written back unchanged"). Value = low: done, and stronger.
3. "Types guard our code, validators guard the wire." v2 status = has. Serde decoding at the link and HTTP edge. Evidence: `crates/fleetdeck-proto/src/command.rs`, `crates/fleetdeck-proto/src/mutation.rs`. Value = low.
4. Types only help if a type-check gate runs (esbuild strips without checking). v2 status = has. `make check` runs clippy `-D warnings`, web typecheck, lint, drift test. Evidence: `Makefile`, `tools/check.sh`. Value = low.
5. A committed build artifact (`fleetd.bundle.mjs`) must be rebuilt in the same commit, or CI must diff it. v2 status = partial. Generated TS types have a drift test. Whether the built board (`web-dist` or embedded assets) is committed and checked for staleness was not confirmed. Evidence: `Makefile` `ts-types`; `.github/workflows/v2.yml` not read in full. Value = medium: confirm that the board assets inside the binary are built in CI and not committed by hand.
6. Never quarantine a test to make a change pass ("test suite is trust"). v2 status = has. Evidence: PLAN.md Adapters L20 and the replay fixtures; `docs/v2/TESTING.md`. Value = medium: state it as a rule in TESTING.md if it is not there (not found by name).
7. Do not make a flag-day reorganize commit; fold a file move into the commit that already touches it. v2 status = not applicable. Value = low.
8. Do not convert a file while another session is mid-pillar in it; heed the "another session touches this file" warning. v2 status = has (the file-ownership rule in the owner's CLAUDE.md). Evidence: `/home/luismorales/.claude/CLAUDE.md` OWNED FILES rule. Value = low.
9. Avoid TS features that strip-only runtimes cannot run (enum, namespace, parameter properties); use `import type`. v2 status = not applicable to the build (Vite/tsc). Evidence: `web/` uses Vite; `verbatimModuleSyntax` not checked. Value = low.
10. Target layout that mirrors "provider-free core / provider adapters / orchestration / http". v2 status = has. Crates split proto, core, providers, deck, station, link. Evidence: `crates/`. Value = low.
11. Exit rule: "new code is typed, touched code converts, 100% is not required at the cut". v2 status = not applicable. Value = low.

## docs/v1/phase3-bun-test-lane.md
- Summary: A record of the first `bun test` run, 111 flat files, 83 green, 820 of 895 assertions. It sorts all failures into categories A to I by root cause. Marked superseded: Bun became the only runtime. The method and the root causes are the useful part.
- Ideas and lessons:
1. Run an unknown lane per file and record the failure by root cause. Do not skip or weaken tests to force green. v2 status = has as a habit. Replay fixtures and live smoke are separate lanes; live smoke is opt-in behind `FD_LIVE_SMOKE=1`. Evidence: `crates/fleetdeck-cli/tests/cutover.rs`, `make smoke-live`. Value = low.
2. A batch `bun test` of 111 paths ran zero tests and exited 0 (false green). Check that a runner counted tests, not only its exit code. v2 status = partial. `bun test` in `web/` and `cargo nextest` are used; a "ran at least N tests" guard was not found. Evidence: `tools/check.sh` (not checked line by line), `Makefile`. Value = medium: a cheap guard against a silent zero-test pass.
3. Bun writes its summary to stderr; capture with `2>&1`. v2 status = not applicable to the logic; relevant to `tools/check.sh` if it parses output. Value = low.
4. Runtime identity regex (`/proc/<pid>/exe` = node|fleetd) refused a valid daemon under another runtime. Lesson: an identity gate must match the real shape of every shipped host. v2 status = has. Process identity uses start time and boot id; a reused pid is "lost, not reattached". Evidence: `a_reused_pid_with_another_start_time_or_boot_id_is_lost_not_reattached` (PARITY.md), `crates/fleetdeck-providers/src/host/shim_tests.rs`. Value = low: done, stronger than a name match.
5. Tests that reach module internals through a test-only hook (`__setInterfaces`) break when the module system changes. v2 status = has (injected `Clock`, id sources, fakes). Evidence: `crates/fleetdeck-core/src/clock.rs`, `crates/fleetdeck-testkit`. Value = low.
6. Environmental flake: lingering test daemons hold ports ("belongs to another daemon"). v2 status = partial. Tests use scoped homes and fake agents; port isolation per test was not confirmed. Evidence: `crates/fleetdeck-testkit/src/node.rs`, `docs/v2/TESTING.md`. Value = medium: use port 0 (ephemeral) and a scoped tmux socket in every integration test.
7. Narrow runtime difference: a path with a literal `?` was split as a URL query. v2 status = not applicable (Rust paths). Evidence: not found. Value = low.
8. Do not blame a new seam without an isolated repro on both channels (the DB table check). v2 status = not applicable now. Value = low; keep the method.
9. Nested `test()` is rejected by a shim. v2 status = not applicable. Value = low.
10. Hung-response timeout semantics differ by runtime (`rawRequest`). v2 status = partial. Link and HTTP timeouts exist; a hung-peer test per transport was not confirmed. Evidence: `crates/fleetdeck-link/src/transport.rs`, `crates/fleetdeck-link/src/reconnect.rs`. Value = low.
